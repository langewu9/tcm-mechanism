## 发现并修复的问题

| 问题 | 修复前的可复现行为 | 当前行为 |
| --- | --- | --- |
| 重复表头生成的后缀碰撞 | `Gene,Gene,Gene_2` 被处理成两个相同的 `Gene_2`，转为字典后覆盖其中一个值 | 为后缀避让已有原列名，得到 `Gene,Gene_3,Gene_2`，三个值完整保留；CSV、TSV、XLSX 验证通过，共用解析器也用于上传元数据 |
| 精确手工映射仍被宽松匹配替换 | 选择 `Gene-Symbol`，却因去标点后的名称相同而读取前面的 `Gene Symbol` | 完整列名精确选择优先；宽松匹配出现多个候选时要求明确选择，不猜列 |
| API 映射字段名与服务不一致 | 网页提交 `geneColumn/log2FcColumn/...`，服务只读取 `gene_column/log2fc_column/...`，手工映射可能被忽略、落回自动选择或报未识别字段 | 识别现有 API 的六个映射键，同时兼容服务内部旧键名；端到端确认使用用户指定列 |

5 项新增回归分别先复现上述失败，再通过修复。新任务版本为 **`proteomics-py-1.10`**，旧 `1.9` 及更早任务不补算。不能仅凭发现解析缺陷就断言某个历史结果错误；需对该任务实际表头与已保存映射单独核对。

另外，逐行 QC 中的 `invalid_p_value`、`invalid_fdr` 现在显示为中文数值范围说明，不改变原错误代码或行结果。PDF 的圆点和页脚分隔符原先在中文字体下出现缺字方框，改为普通连字符；报告数值不变，修复前文件作为证据保留。
