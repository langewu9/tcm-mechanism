## 修复的三个问题

### 1. 已有长成分名称不能检索

原目录允许实体名称最多 300 字符，但查询序列化器和前端单项校验只允许 120 字符。TCMSP `Sheet1` 第 **80790、225559** 行的一条 **156 字符**完整成分名称实际请求返回 400（字段长度错误），不是资料不存在。

现允许完整成分名称最多 **300 字符**，中药仍最多 **120 字符**，每次最多 **12 项**；同一限制也应用于保存关系查询。超过边界仍拒绝，不截短名称。该完整名称跨 TCMSP、TCMIP、HERB 共 34 个有效原行，查询保留 3 个来源成分身份、17 个来源靶点身份、68 条关系，完整任务 #26 验证通过。

### 2. 化学名称中的逗号被当成批量分隔符

HIT `Sheet1` 第 **187227** 行实际成分名为 `Peiminine,Simperialine`（该行原靶点 `BCL2`），原前端会提交 `Peiminine` 和 `Simperialine` 两个词。新增回归先复现该错误，再修复。

成分输入现为 **每行一个完整名称**，逗号、斜杠、分号、竖线等标点属于名称，不再自动拆分；原位置的输入框改为可换行文本框，沿用原 `field` 样式，页面布局和 CSS 未改。中药原有批量分隔方式保持。浏览器实测该名称返回 18 条来源关系、3 个来源靶点；与 156 字符名称分两行输入返回 86 条关系、20 个来源靶点，原始名称均完整保留。

### 3. 交集页不能正确使用已有中文疾病查询组

修复前只按疾病原词精确匹配：同样查询“石榴皮”，英文 `Pulmonary fibrosis` 读到 8,325 个疾病侧来源名称键，中文“肺纤维化”却读到 0，并显示未匹配疾病。

现复用 main 已有疾病查询扩展表，再对每个扩展词做 **精确目录匹配**，不新增疾病子串推测或实体身份合并。新任务记录扩展词、别名来源与提交版本；网络统计读取版本更新为 **`main-078d374-candidate-statistics-v4`**，历史记录不重算。原 API 支持的超过 120 字符的疾病名称继续保留字面精确查询方式。

这是沿用旧版的查询分组，不证明扩展词之间具有严格医学同义关系；实际匹配疾病名称和来源继续保留。中文和英文样例现在均读到同一批 `Pulmonary fibrosis` 证据，疾病端 8,325 个来源名称键；石榴皮中药端 1,797 个来源身份、1 个疾病—中药直接关联候选，严格交集 **0**。另以白茅根检查同样行为，来源行集合也一致。

**严格交集 0 不代表已经证明没有共同生物学靶点。** 当前两侧来自独立来源实体，物种和权威编号未核实。离线诊断中石榴皮两侧有 73 个规范化名称重叠、白茅根有 44 个；这些只记录在验收报告，不写成严格交集或规范身份。真正的跨来源分子对应仍需权威映射资料，不能为了得到非零交集按同名强行合并。

## 与旧 main 不同但未当作查询错误的行为

- **查询范围不同**：旧版中药/成分使用子串匹配。例如“麻黄”旧分支取到 17,621 个原行，包含麻黄根、炙麻黄等；当前精确“麻黄”为 10,653 个有效原行。“当归”旧版 7,239 行，当前 5,263 行，HIT 的“当归干浸膏”487 行单独查询保留。没有为追求相同数量混入其他药名。
- **名称拆分不同**：旧 Excel 分支按通用分隔符拆靶点，旧 SQLite 分支又以整格名称计靶点清单，两者自身可能不同。例如 TCMSP 第 2936 行 `Prostaglandin G/H synthase 1` 含名称内斜杠。本次沿用导入时已确认的 single 模式保留整格原名称，未改回猜测拆分。
- **身份和计数不同**：旧版按名称去重，当前保留来源内身份；同名实体跨来源或 HIT 原编号不同可以分别计数。所有差异保留相应原行和来源，不将旧显示总数当作正确性的唯一依据。

旧 Next.js 路由中的其他名称解析/别名行为、全站视觉对照、权威身份核实及真实实验统计不包含在这份 Python 查询对照的通过范围。
