# 中药查询先过滤再限量修复（2026-10-21）

## 完成范围

修复批量中药检索和网络药理查询中“无关的成分—靶点记录先占满候选上限，导致本药材合法记录未被读取”的问题。现在先在数据库中判断来源支持，再应用原有数量上限。

本次没有处理 HIT 的 62 行缺少靶点名称记录，没有导入完整工作簿，没有修改 UI、模型配置、外部接口或历史研究结果。工作保存在本地分支，未推送远程。

## 修复方式

两处查询共用 `supported_target_queryset`：

- 限定成分必须来自本次已经读取的中药—成分关系。
- 对旧 SQLite 三元组来源，使用数据库 `EXISTS` 判断是否有本次选中的中药边，且成分实体、来源版本和原始行号全部一致。
- 对 `sourceRowId` 做严格 JSON 整数检查，防止字符串、布尔值和浮点数因数据库宽松比较而占用有效名额。SQLite 和 PostgreSQL 分别验证。
- 普通图谱的独立成分—靶点注释保留既有语义；来源元数据中没有 connector 的记录不会因为 SQL NULL 比较而被误排除。
- 保留原有启用状态、端点可见性检查和最终 Python 来源核对。`EXISTS` 不会因多个中药支持同一关系而重复返回目标边。

没有取消或调高限制：批量检索仍是每类关系 1,200 条；网络默认每阶段 12,000 条，原始导出另有 4,000 条上限。现在目标关系的上限按通过来源检查的关系计算。真正超限时，原有截断标记和前端提示继续生效。

中药—成分阶段本身仍有上限；若其合法记录已超限，后续结果仍可能不完整并保留提示。本次修正不等于取消所有部分结果情况，也不等于全量数据库部署验收。
