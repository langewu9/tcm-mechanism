# 医案候选与网络药理关联边界核验（2026-10-22）

本轮只修补已有医案候选确认、确认后的本地证据链和关联网络药理任务。没有接入模型或外部数据库，没有创建新业务模块、迁移或目录资料；React 仅在原证据链区域显示来源不可用提示，布局及 CSS 未改。工作分支为 `codex/existing-feature-audit`，本轮不推送远程。

## 可复现问题与处理

| 临时合成数据复现的问题 | 修补 |
| --- | --- |
| 确认证据链沿实体类型遍历，纳入停用关系来源或停用端点来源 | 复用既有启用/活动检查；停用根候选不会进入本次显式重建的证据链，并说明排除原因 |
| 共用成分带入其他中药、其他版本或无效行号的靶点及后续通路 | 复用 `supported_target_queryset`，旧三元关系按同来源版本、同整数原行筛选，先过滤再限量；普通图注释仍保留 |
| 仅端点类型相符就将 `does_not_contain` 等关系当作组成路径 | 使用现有网络药理的关系类型集合及证候—方剂关系，不为未知谓词猜测含义 |
| 已停用、来源不可用或实体类型不符的候选仍可确认 | 服务端拒绝接受，不改候选状态、审计结果或任务结果；仍允许显式驳回以纠正旧确认 |
| 归档医案仍可发起关联网络任务，排队后归档也未拦住 | 请求入口拒绝已归档医案；完整 worker 再检查状态，失败不发布快照行，旧成功任务保留 |
| 恰好达到关系上限但没有遗漏时仍标截断 | 只有实际读取到额外的合法关系才标记截断；真实超限继续提示 |

新确认链版本为 `case-confirmed-evidence-2`。按原有层级顺序收集证候、方剂、中药、成分、靶点、通路，避免同时确认证候和方剂时先访问共享成分、后得到另一条合法中药原行。来源与端点编号、原行号、版本和校验值保存到确认链；不合并同名实体、不补物种或规范编号。

## 并发与历史边界

- 请求创建、同步保存及后台执行均校验当前候选/医案；完整 worker 在事务内先锁医案，再锁候选/来源任务，与人工审核和原同步路径保持相同顺序。避免确认与分析反向占锁；取得医案锁后，归档须等待该事务结束。
- 两项 PostgreSQL 实际并发检查分别验证：worker 持有医案锁时另一个连接得到 `55P03`；人工审核先持有医案锁时，worker 等待医案且不先占候选，待审核释放后能完成。第二项通过 `pg_stat_activity` 的实际锁等待状态同步，未用任意固定睡眠当作成功证据。SQLite 不支持同等行锁，两项明确跳过。
- 仅在研究者/管理员明确确认或驳回时更新该任务的审核状态及确认链，保留已有观察、模型信息、检索上下文。普通 GET 不读取今天的目录重建历史结果；其他任务不批量改写。
- 历史确认链可能包含后来停用的来源，读取时保留其历史含义；新确认/显式重建按当前状态检查。不是自动修正所有历史结果，也不是宣称旧数据从未受过任何影响。
- 仍保持原来最多 1,000 条确认链关系的有界语义；这不是无限量的完整医案科研证据导出。另行创建的完整网络药理任务继续使用已有冻结、权限和失败机制。
