## 数据保护与发布规则

- 七个文件的 SHA-256 与首次核验完全一致；原 Excel 只读保存。
- 先逐源完整扫描，再分批暂存；文件校验、原始行/关系/隔离数量均对账通过后，事务内发布当前版本。失败/中断不使半成品关系生效，可按已提交行继续。
- 七库重复运行全部返回 unchanged，未新增原始行或关系。
- 与导入前一致性备份相比，23,221 个旧实体、旧 UUID/PK/stable_id/标签/元数据、旧权威绑定与外部标识、104,714 条旧映射、17 个旧分析任务、1 个数据集及 20 行数据、120 条旧组学结果、24 个旧图表产物和用户记录均无变化。
- SQLite foreign_key_check 无违规，quick_check 为 ok。当前本地库为 python_app/var/qa.sqlite3；未重建旧 data_cache.db，未删除原数据库、历史任务或模型。
- 原始授权数据、运行数据库、来源快照与本地日志不公开上传 GitHub。本次没有提交或推送远程仓库。

## 链路验证

使用网站同一数据库的只读黄金样例：

- 黄连：命中 6 个来源范围的中药实体，返回 177 个成分、244 个靶点、1,385 条关系。靶点关系达到 1,200 条查询上限，界面/JSON 均明确标记截断，不称为全库总量。
- 中文“阿尔茨海默病”：通过既有别名检索，命中两个来源的疾病实体；当前返回 499 个中药实体、48 个靶点、1,200 条关系，标记截断。
- 黄连 + Alzheimer's Disease：1,200 行有界检索得到 6 个直接关联靶点；严格跨库交集仍为 0、通路注释为 0。选中中药的三元证据优先读取，避免被其他中药记录挤出。名称相同/物种未知不用于伪造严格交集或通路注释。
- 真实黄连检索快照（任务 20）的 R 圆形图输入为 77 个节点、118 条边，来源快照为 427 节点/464 去重展示边。离线四格式渲染及网站实际绘图任务 22 均成功，网页显示交互网络与 SVG/PDF/PNG/HTML 下载入口（产物 33–36）。修复了边证据列表被当作单个字符串处理的错误；保留证据字段/列表，不以演示图替代。
- 本地 SQLite 使用 WAL 与 30 秒锁等待，避免长目录读查询阻塞绘图任务提交，不降低默认持久性。生产 PostgreSQL 不受该设置影响；本次没有做 PostgreSQL 全量数据验收。

WAL 模式备份必须使用 SQLite 在线 backup API 或经过验证的完整备份流程，不应在运行时仅复制主 .sqlite3 文件并忽略未检查点的日志。本次导入前使用在线 backup API 创建独立一致性备份。联调新建任务不覆盖历史任务；失败任务也保留以便审计。

自动化验证：128 项相关 Django 测试通过；前端来源、网络导出、研究检索与 R 页面测试通过；TypeScript/Vite 构建通过；OpenAPI 校验无警告；R 交互安全与样式契约通过。
