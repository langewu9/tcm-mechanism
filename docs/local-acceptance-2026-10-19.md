## 旧数据试导入与发现的问题

只读核对的工作表与 main 的 `SOURCE_FILES` 字段映射一致：BATMAN、HERB、HIT、TCMIP、TCMSP。原压缩包和工作簿未被修改。工作表声明行数不等于已核实的有效记录数。

TCMSP 试导入取 `Sheet1` 第 2–101 行。原 XLSX SHA-256 为 `1482cd795f3396b917bebf74046009a1a529e71c2984d8aa376fa4069777d986`；生成 SQLite 中保留原工作表行号和文件哈希，另有来源清单。数据库连接器的快照哈希包含文件名、数据库字节以及存在时的 WAL，与普通文件 SHA-256 的范围不同。

本地来源名称明确为“TCMSP 旧版样本（100 行，仅本地验收）”，没有将它标记为完整或最新数据集。真实 HTTP/worker 通过了连接检查、只读预览、应用、重复应用拒绝和来源版本/记录溯源。

发现并修补：

1. main 的旧缓存构建器重新遍历工作表时会把表头当成数据，三类表均已改为从第二行读取。保留原 `backend/data_service.py` 作为冻结对照，列映射由不依赖 pandas 的独立模块供缓存构建器使用，并通过测试核对与冻结 main 完全一致。
2. “靶点基因”列实际包含蛋白全名；明显的名称不再自动写入 symbol，形似符号的值也明确标为未核实，没有声称 HGNC/UniProt 映射完成。
3. 单个蛋白名称中的逗号曾被拆为两个靶点。新增 `targetCellMode=single|list`，旧缓存默认 list 保持兼容；本样本设为 single，保留名称内标点。来源表单提供相应选择。

第一次 list 配置试导入得到的 74 实体/201 关系属于已纠正的历史结果。single 配置产生新的来源版本，最终有效结果为 73 实体/200 关系，旧错误记录停用且历史保留。最终记录为 `python_app/var/legacy-source-acceptance-final.json`，其中预览 ID 3、应用 ID 4。

全量旧库、跨来源同名歧义、规范基因/蛋白标识、来源许可和真实科研结果对照仍待进一步核实；100 行样本通过不等于五个旧库已完成迁入。源文件和预览准备工具为 `tools/prepare_legacy_preview.py`，它拒绝覆盖已存在的预览文件，不覆盖原工作簿。

## 目录关系图接入与首轮一致性检查

在现有 `/research` 工作台的中药/成分检索结果区增加绑定入口，复用 `KnowledgeNetworkGraph` 与 `RAnalysisGallery`，没有增加独立业务模块或替换工作台布局。先保存本次关系查询，再由原有 Celery/R 私有工件流程生成图表。已保存结果通过 `/research?catalogTask=<id>` 恢复，并展示来源版本、记录号、数量口径及检索 SHA-256。

为避免按名称误连关系，批量检索新增关系 ID、两端实体 ID、来源版本 ID 和结果哈希。保存接口只接收查询词和预期哈希，服务端重新查询本地目录；结果变化时返回统一 `CATALOG_RESULTS_CHANGED` / HTTP 409，要求重新检索。图表随后使用保存的快照，后续目录变化不会改写历史图。无关系时拒绝生成，截断明确标记，同名不同 ID 不合并。

目录查询为已有本地数据的同步查询；只有完成实际查询并保存快照后才产生 succeeded 任务，R 绘图仍由后台 worker 执行。快照最多保留 5,000 个节点和 5,000 条来源记录，R 再按现有 80 节点/500 连线上限选择展示子图。快照按来源记录 ID 去重，R 图按无向端点对合并重复连线，两类计数分别展示。

真实本地验收：`tools/smoke_catalog_figures.py` 使用既有 TCMSP 历史样本与隔离验收账号，只读目录，不修改旧表或来源数据。任务 ID 11、R 子任务 ID 12 形成 73 节点、200 条来源记录、155 对去重连线；R 输入实际为 73 节点/155 边，四种私有导出 SHA-256 验证通过。研究者 B 读取 A 的任务、图表均为 404，超级管理员读取仍保留 A 的所有权；重复绘图复用同一子任务，错误检索哈希返回 409。详细记录位于私有忽略目录 `python_app/var/catalog-figures-acceptance.json`。

345 项 Django 回归、7 项新增快照测试中的统一错误码检查、OpenAPI 和迁移漂移检查通过；前端 HTTP、工作台请求顺序、图表组件绑定/刷新恢复/过期响应隔离、R 目录回归及交付构建通过。浏览器原生确认框仍不作为已完成的界面点击验收，本次真实链路验证使用 HTTP 和真实 worker/R，组件交互由离线回归覆盖。
