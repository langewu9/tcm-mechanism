# 网站优化续作（2026-10-09）

基于独立修复分支 `codex/collaboration-priority-fixes` 续作，并同步同一 PR；不覆盖 main、合作分支或原始工作目录，不改数据库源文件和模型。

## 数据源更新配置闭环

超级管理员在“数据源同步”卡片展开“刷新计划与启停设置”，可修改启用状态、每 1–8760 小时刷新间隔；留空代表仅人工触发。保存调用 `PATCH /api/v1/admin/sources/{id}/`，只允许 `enabled` 和 `refresh_interval_hours`，拒绝配置/路径/连接器等额外字段，遵循现有 Session/CSRF 校验。更新前后值和操作者记录在 Django 管理日志中。

保存刷新间隔不会开启服务器总开关，不代表 beat/worker 已在运行，也不会立刻调用外部接口。定时预览继续依赖上一轮部署开关和调度服务。停用不会删掉版本、证据或研究记录，也不撤销已经运行完成的入库。

## 同来源同步串行化

人工预览、人工审核 apply、定时预览都在创建运行记录前锁住 DataSource，并检查同来源 pending/running 记录。已有活动任务时返回 409 / `SOURCE_SYNC_ACTIVE`，不再投递第二个任务；网页对应操作同时禁用。已申请过同一预览 apply 的错误合同保持不变。

生产 PostgreSQL 行锁负责并发串行化；SQLite 用于本地测试，不承诺相同并发保证。任务崩溃遗留 pending/running 时必须核对队列/日志后处理，不能绕过保护强制启动。后台直接编辑 SyncRun 等管理操作仍需审慎，本轮没有实现自动恢复或任务撤销。

## 页面加载与交互

业务页面使用 React lazy + Suspense 按需加载；首页和登录/注册保留直接加载。增加加载提示及资源加载失败时的刷新/返回首页入口。保留原有样式体系与 R/生信分析接口，没有替换算法或虚构可视化数据。

数据源设置表单阻止同步重复点击，处理接口错误和卸载后的迟到响应；数据源列表使用读取版本标识，避免旧轮询响应覆盖新保存的配置。增加 `test:sources` 离线前端回归，并接入 GitHub CI。

## 验证边界

在独立副本运行后端全量测试、OpenAPI 校验、模型漂移检查、前端回归/TypeScript/生产构建。使用合成测试数据和隔离 SQLite 测试库；不迁移或写入用户原数据库。前端构建入口从上一轮约 538 KB 降至约 307 KB（约减少 43%，非实际网络加载时长）。容器端、生产 PostgreSQL 并发和真实供应商服务仍须部署环境验收；不能把离线通过视为产品已全面上线。
