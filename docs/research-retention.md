# 研究资料归档与恢复

2026-10-19：落实研究者资料保留在服务器、按所属用户访问、平台超级管理员可查看全部记录的要求。

## 行为

- 数据集和医案的 `DELETE` 改为归档，仍返回 204。原始文件、解析行、医案当前正文、所属用户、已有分析任务和结果保持不变；归档不取消已经提交的任务。
- 普通列表和研究总览不计入已归档资料。列表可传 `archived=true` 查看归档，`archived=all` 查看两种状态。每种状态仍执行所属用户过滤，超级管理员可查看全平台记录。
- `POST /api/v1/research/datasets/{id}/restore/` 和 `cases/{id}/restore/` 恢复原记录，保留原 ID 和所有者。重复归档或恢复不重复写审计事件。
- 本人和超级管理员可读取归档资料详情、私有原文件及审计。归档状态不能修改或用于发起新的分析，须先恢复。已有任务和工件仍由原所有者权限保护。
- 数据集原始文件一经保存，不接受覆盖替换；修改后的文件需另存为新数据集。名称、说明等元数据仍可编辑。
- 前端沿用已有布局和样式，增加使用中/已归档筛选、归档及恢复操作。

## 溯源与保护

- `core.0023` 新增归档时间、归档操作者和数据集审计表。历史资料默认未归档，不猜测或回填历史事件。
- 数据集上传、归档、恢复记录操作者、所有者、时间和原文件 SHA-256。`GET .../datasets/{id}/audit/` 按所属用户检查访问权限。
- 医案沿用原审计表，新增归档和恢复事件，审计只保留字段变化和哈希，不复制医案正文。
- `core.0024` 保护医案审计操作者账号，避免恢复后删除账号导致操作人不可追溯。已有操作者为空的历史记录保持原样。
- Django Admin 禁止直接删除数据集和医案、编辑或删除审计。数据集管理字段只读，上传仍经过已有解析和权限接口。常规模型及 QuerySet 的硬删除也被阻止。
- 归档和审计写入同一数据库事务，审计失败时回滚归档状态。永久清理入口未开放，后续需明确保留周期和管理员清理策略。

## 验收

自动回归覆盖：原始文件/行数/哈希不变，分析任务关联不变，A/B 研究者隔离、管理员恢复不转移所有权、请求伪造归档/所属用户无效、CSRF、重复调用、审计失败回滚、后台和常规 ORM 删除保护、审计操作者保留。

本机已通过真实 HTTP 上传、Redis/Celery 分析、CSV/XLSX/PDF 导出、归档后原件下载、管理员恢复和跨用户拒绝访问。输入明确标注为合成验收资料。

归档保留当前资料，不等同于已实现医案每次修改前的全文版本恢复。数据库备份与私有文件备份仍须分别配置并在正式环境做恢复演练。
