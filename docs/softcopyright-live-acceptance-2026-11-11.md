## 两个确认的待处理问题

### 1. 大目录检索耗时较长（P2）

本环境对「粳米」的实际 HTTP 检索为 **40.437 秒**；另一次独立查询采样 6 条 SQL 合计 **22.728 秒**，其中两条关系查询分别约 9.34、9.50 秒，疾病侧关系查询约 3.86 秒。查询日志保存在本地，不能仅凭这次采样断言只缺某一个索引。

worker 记录：完整目录任务 #50 约 74.812 秒，网络任务 #52 约 65.615 秒，科研报告 #53 约 62.326 秒。作为对照，1,200 行分析 #45 约 5.264 秒，首次 R 火山图 #46 约 2.366 秒。

这些是单机单次观测，不是并发压测或 P95。验收 PostgreSQL 使用 32 MB shared_buffers、单个 worker；尚未按生产资源调优。需要继续检查执行计划、关系检索方式及重复查询，再按目标数据量和并发需求复测。当前不宣布性能验收通过。

### 2. 火山图图注没有完整说明 FDR 筛选规则（P2）

`python_app/apps/core/services/visualization.py` 生成的图注为「筛选阈值：|log2FC| ≥ 1，P ≤ 0.05」。但当前分析在有 FDR 时按 FDR 阈值筛选，否则才用 P 值；绘图颜色正确使用保存的 selected 状态。

本例有 **37 行**通过 log2FC/P 条件但未通过 FDR，正确地没有入选。因此这是已确认的**说明不完整**，本轮没有发现这 37 行被错误选中。后续应明确区分「P 值参考线」和「保存的筛选规则 / FDR 优先」，保留历史结果，不重算或悄悄替换旧图。
