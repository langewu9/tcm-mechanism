**这 1,684 个文件只能称为“未登记候选”，不能据此认定为中断残留、测试垃圾或可删除文件。其来源、历史环境和是否另有使用者尚未核实。** 本轮没有删除、移动、覆盖或自动修复它们。首次默认输出最多 200 条，结果明确标记 incomplete；随后以 `--max-findings 3000` 重做，完整列出 1,684 条。清单只保存 storage key 的 SHA-256，不复制文件名、研究内容或私有路径。

本轮前后逐行计算三张表的 PostgreSQL `row_to_json` 文本 SHA-256：44 条任务、48 条工件、6 条数据集的原记录均未改变、丢失或增加。此结论仅针对这三张表，不等同于整个数据库逐字节不变；服务健康请求、会话和运行日志不在该证明范围。

## 已修补的下载边界

修补前用临时数据库、合成文件运行 8 项检查，实际出现 6 项失败：包括同长度文件损坏、任务仍 running 的残留登记、符号链接文件等仍返回 HTTP 200。基线日志已保留。

现在下载先按既有规则鉴权，再核对以下事实：

- 父分析与绘图任务均已成功；所有者、父任务编号、图表类型和输入哈希一致。旧记录没有 parent FK 时只接受已有参数和结果一致的绑定，不猜测、改写历史。
- 工件记录与任务结果清单中的编号、格式、文件名、大小、SHA-256、渲染版本和下载地址一致。
- 本地存储通过 no-follow 目录文件描述符逐级打开，仅允许普通文件，不跟随符号链接或读取设备/目录。
- 实际读取不超过现有 10 MiB 工件上限，并核对实际大小与 SHA-256。HTTP 响应使用刚验证过的字节副本，不重新打开可能已变化的原文件。

缺失、损坏或登记不一致统一返回 HTTP 503 / `ARTIFACT_UNAVAILABLE`，不泄露路径或异常堆栈，不改写原任务、删除文件或自动重绘。所有权过滤和原有下载安全响应头保留。原有访问审计中间件未修改；它对成功敏感访问落库，不能声称本轮增加了失败访问审计。

下载现在需要读取和哈希整个工件，再返回验证副本；大小上限限制单文件开销，但并发请求仍消耗相应内存和 CPU。本轮未进行负载测试。非本地存储的单次打开适配仅用合成适配器验证，真实 S3/生产存储尚未验收。

## 只读盘点工具

新增 Django 命令 `audit_result_files`，默认只扫描配置的本地 MEDIA_ROOT 下 `analysis-artifacts/` 与 `research-datasets/` 两个已有命名空间：

```bash
# 使用与你的环境匹配的启动方式；本机验收配置示例：
python_app/.venv/bin/python tools/postgres_acceptance.py manage audit_result_files --max-findings 3000
```

命令没有 apply、删除或重试选项。PostgreSQL 下显式使用只读可重复读事务；文件系统仍是实时观察，不能宣称数据库与文件系统共同拥有原子快照。读取期间检测到文件变化会报告 incomplete。

默认上限：10,000 条登记记录、10,000 个文件系统条目（包含目录）、200 条输出发现、2 GiB 哈希读取量。达到上限会标记 incomplete，不把未核对登记的文件误报为无引用文件。仅支持标准本地 FileSystemStorage，其他后端明确返回 unsupported，不枚举远程对象。命令输出 JSON，发现问题或不完整时仍可能正常退出；操作人员必须检查 `status`、`complete`、`incompleteReasons`，不能只看进程退出码。

路径恰含运行任务编号的文件仅标记 `unregistered_path_with_active_task_id`，不是证明其被该任务占用，更不是判定任务死亡的依据。

## 真进程退出演练

新增可重复运行工具 `tools/probe_artifact_commit_interruption.py`，必须显式 `--run`。工具自建并核对临时 SQLite、媒体目录和所有权标记；不连接工作数据库、Redis、模型或 R 服务，不停止已有进程。输出要求新文件名和私有目录。

子进程执行真实绘图持久化逻辑，以合成 R 响应代替网络；在第一个文件保存、工件 INSERT 执行后，事务提交前调用 `os._exit(73)`，跳过 Python 异常清理。最终 **16 项断言全部通过**：

- 真子进程按 73 退出，工件 INSERT 回滚；一个文件留存，任务没有被错误发布为成功。
- 没有已发布工件记录，因此不能通过工件下载编号取得该残留；盘点识别到候选。
- 原有维护命令默认预览不修改状态；仅在此自建临时环境、子进程已退出后显式 apply，任务变为失败，不重新排队、不清理文件。
- 正常对照提交四条工件，SVG/PDF/PNG/HTML 下载字节一致；其他账号被拒绝。最后仍只报告一个候选文件。
- 自建临时环境已移除，工作库与工作文件未被演练修改。

第一次工具运行因错误传入任务 ID、而实际服务需要 AnalysisTask 对象，未到达退出注入点；修正工具调用后重新运行得到上述通过结果，失败报告也保留。演练验证的是 SQLite 下文件/事务分离的窗口，不等于 PostgreSQL 崩溃、整机断电、对象存储或所有 worker 故障均已验收。PDF/PNG 为明确标记的合成传输字节，不能作为真实 R 图像格式或科研结果正确性的证据。
