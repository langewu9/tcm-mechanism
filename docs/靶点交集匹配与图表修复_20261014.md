## 名称解析

精确目录名称及已发布、已映射的来源名称可参与查询。新增 whole-term 中英文查询对应表 `disease_exact_aliases.json`，如“肺纤维化”仅对应“Pulmonary fibrosis”。中文与英文目录记录可一并读取，但不会合并实体主键或 UUID。

原来的正则疾病扩展表保留为检索建议；不能自动把泛称、亚型和更宽的疾病类别并入同一交集。例如一般肺纤维化记录缺失时，不退回到特发性肺纤维化或间质性肺疾病。相关候选需用户选择确切名称，再提交查询。

响应及新任务快照保留 `diseaseResolution`：输入、解析状态、实际命中词、规则版本、截断标志、候选名称与来源。停用来源、非活动实体和歧义来源映射不作为自动命中。病名控制字符在请求端拒绝。

## 图表口径

- 未匹配名称：提示“名称待确认”，不把无数据当作零靶点，不画重叠圆。
- 名称已匹配但无一侧证据：提示“证据不足”，不作无生物学关联结论。
- 两侧有数据且交集为零：画两个分离的圆。
- 非零交集：按集合关系显示相交、包含或完全重合。
- 所有圆为集合示意，明确注明面积不代表数量；长名称、说明在 SVG 外，完整保留并自动换行。
- 源关系或实体读取被截断、部分中药未匹配、方剂组成缺失：标为“部分结果”；仅显示当前返回子集，不称为全库总量。
- 严格交集仍按相同实体主键计算；同名、未知物种、未验证跨库标识不会自动合并。
- R 统计图入口拒绝未匹配或缺少一侧证据的任务；真实零交集仍有效；截断任务的绘图标题注明“当前返回子集”。旧任务不重写。

## 本地代理 CSRF 故障补充

服务重载时，之前由启动进程临时传入的 `CSRF_TRUSTED_ORIGINS` 未继承，读取到空列表。Vite 改写后端 Host 为 `127.0.0.1:8020`，浏览器 Origin 仍为 `http://127.0.0.1:5173`。因此即使获取了有效令牌，中药批量检索和网络药理 POST 也会返回 `CSRF_FAILED`。该故障属于启动配置遗漏，不是查询数据或名称解析错误。

现在 `config/local_security.py` 在 DEBUG 模式且无显式部署来源配置时，仅默认信任本项目的 `http://127.0.0.1:5173` 和 `http://localhost:5173`。显式配置优先，生产模式无开发来源例外；不使用通配符，不关闭 CSRF Middleware/SessionAuthentication。前端原本每次 POST 都重新获取令牌，保持原机制，不为所有 403 自动重试或重复创建任务。

新增真实 Cookie / CSRF 流程测试，验证登录后中药检索、中文疾病交集可以通过同样的跨端口代理请求；缺少/错误令牌及其他域名、其他本地端口仍被拒绝；空来源配置可复现原失败。安全配置、账号/会话 API、疾病解析和网络药理组合共 67 项测试通过，前端 API/研究检索测试及构建通过。
