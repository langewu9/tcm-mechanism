# R 重新生成修复与验收记录（2026-10-31）

本次修复让用户可以明确发起一次新的 R 绘图。服务端根据分析数据运行 R 包，生成图文件，再交给前端展示。已有成功图保留为历史版本。

## 请求与版本规则

接口仍为 `POST /api/v1/research/analysis-tasks/{parentTaskId}/visualizations/`，请求示例：

```json
{"chartKey": "proteomics_volcano", "regenerate": true}
```

`regenerate` 默认为 `false`，兼容原有调用。服务端按父任务、图表类型和输入 SHA-256 查找任务：

| 情况 | 行为 |
| --- | --- |
| 同一输入已有 queued/running 任务 | 优先复用，返回 200；重复点击不再入队 |
| 同一输入已有成功任务，`regenerate=false` 或省略 | 复用成功结果，返回 200 |
| `regenerate=true`，且同一输入没有 queued/running 任务 | 新建绘图任务，返回 202；历史成功、失败或取消记录均不阻止新绘图 |
| 默认请求没有可复用的 pending 或成功任务 | 新建绘图任务，返回 202 |

显式重新生成的新任务以 `previousRenderTaskId` 关联该图表最近一次成功任务；没有成功记录时为 `null`。该编号由服务端确定，可通过原任务详情接口回查。重新生成不为输入哈希添加随机数：相同绘图数据仍得到相同输入哈希。

每代产物归属独立的 `render_task`，使用独立存储路径。旧任务结果、文件记录和文件字节保持可查；新绘图失败或取消时，旧成功图仍可浏览和下载。入队沿用父任务锁，发布沿用运行状态检查和取消保护；用户归属及管理员访问规则保持原有权限边界。

## 数据链路

用户正常上传数据 → Django 校验并完成分析、保存结果 → Celery 执行绘图任务 → R 绘图服务运行绘图包 → Django 校验并保存 SVG/PDF/PNG/HTML 私有产物 → 前端通过鉴权接口浏览、下载。

本次绘图服务版本为 `r-viz-0.4.2`；这是服务的 `rendererVersion`，不是 R 语言本身的版本号。

R 接收绘图所需的受限分析数据，不直接连接业务数据库。前端展示本次任务返回的产物。输入摘要、输出 SHA-256、文件大小及 renderer 版本由任务和产物记录保存。

## 数据库迁移与回滚限制

迁移 `0030_visualization_render_artifact_identity` 将唯一约束从 `(task, chart_key, file_format, input_sha256)` 改为 `(render_task, file_format)`。同一输入可以产生多代图，每个绘图任务每种格式只允许一条产物记录；迁移本身保留已有行和哈希。

产生同一输入的多代产物后，直接反向执行 0030 恢复旧唯一约束会发生数据冲突。部署回滚必须另行设计兼容方案，并保留任务和文件历史；不得为恢复旧约束而删除历史产物。代码回退与数据库约束回退需要分别评估。
