# 多数据库统一主表与兼容规范

日期：2026-10-14。主表与七份工作簿全量导入已完成本地验收；定时同步仍未启用。现有数据、任务、模型和来源文件不重建、不删除。

## 1. 主表结构

| 表 | 职责 | 唯一标识与关联 |
| --- | --- | --- |
| KnowledgeEntity | 统一实体主表：中药、成分、疾病、基因、蛋白、通路、证候、方剂 | canonical_id 为不可编辑 UUID；旧整数 id 与 stable_id 保留 |
| CanonicalIdentifier | 规范 ID 的权威绑定 | 实体类型 + namespace + identifier + taxon_key + scope；一个键只能对应一个实体 |
| SourceEntityMapping | 每个来源版本的原始实体 ID、名称与映射结果 | 来源版本 + 类型 + namespace + 原始 ID + 物种；保留 mapped/unmapped/ambiguous/conflict |
| SourceRecord | 原始来源行 | 来源版本 + 原始记录号；完整 payload 与 SHA-256，不覆盖同版本已保存原文 |
| EvidenceRelation | 统一关联证据表 | 两端引用实体整数主键；来源版本、来源记录号与可选原始行外键均保留 |
| DataSource / SourceRelease | 来源登记与版本 | 来源 slug + 版本；文件校验、授权说明、映射规则版本保存在来源元数据 |

EntityIdentifier 是已有页面/组学服务使用的外部标识观察表，保持兼容。不能把该表的名称别名或“蛋白 accession 对基因”的历史交叉引用直接升级为新主表的生物实体身份。

## 2. 关联规则

1. 全局 UUID 是平台身份，不使用中药名称、成分名称、各库行号或数据库原始 ID 作为全平台主键。
2. namespace 先规范化，再按类型检验格式。支持 UniProt、NCBI Gene、HGNC、PubChem CID、ChEMBL compound/target、STRING、Reactome 与完整 InChIKey；compound/target 的 ChEMBL 命名空间分开。
3. 已知物种使用 NCBI taxon ID；未知明确记 unknown，不能默认当作人类。生物标识缺少物种时先限制在来源范围内；HGNC、人类 Reactome 稳定 ID、STRING 的物种前缀可以提供明确物种。
4. 化合物结构/化学库标识不按来源物种拆分，taxon_key 使用 not_applicable。名称、CAS 或未规范化 SMILES 不直接建立跨库强身份。
5. 同一强 ID、类型与物种可以复用已有主表实体。仅同名、同义词相似或蛋白名相同不自动合并。基因与蛋白是不同实体，可在后续增加 encodes 关系，不能以名字相同当作同一个实体。
6. 一个标识指向不同既有主表实体时记 conflict，保留原绑定与冲突提议，不覆盖、不删除。历史别名指向多个实体时记 ambiguous，不取第一条匹配。
7. identity_status 的 identifier_bound 表示按强标识建立绑定，不代表所有外部 ID 已逐条在官方接口重新核验，也不代表药理/疗效证据。

## 3. 原有七份工作簿的兼容口径

- BATMAN：保留 CID、Gene ID、Gene Name 与原始 Score；预测评分、字符串证据说明不相互替代。
- HERB：Herb ID 保留来源范围，成分/基因名称单独保存，不仅按名称跨库合并。
- HIT：分别保留 Herb/Compound/Target ID、PubChem CID、ChEMBL ID、UniProt 与 Symbol；化合物 ID 和靶标 ID 不混用。
- TCMIP：保留相似得分、Activity 与参考文献原文，不把相似分当活性值或跨库总分。
- TCMSP：靶点字段可能是蛋白名称，不一律解释为已核验人类基因符号。
- 疾病—中药与疾病靶点汇总：保留疾病原名、来源文件及中药—疾病—靶点三元语境。三元关系不能直接当作全局疾病独立靶点结论。

原工作簿继续只读保存。`legacy_workbooks.py` 按实际表头解析；`workbook_import.py` 实施两遍流式审核/入库。疾病关系使用 disease_herb、disease_herb_target、herb_disease_target、disease_target，并在三元关系中保留双方 stable_id 上下文。

本地当前数据库已保存 2,508,850 行原始数据和 5,018,040 条关系；63 行缺失靶点隔离保留。全库实体 109,945 个（含此前 UniProt/Reactome 目录）；仅有强标识及已核验物种依据时跨来源复用。工作簿内部授权不等于可公开分发，原始 Excel、数据库文件和来源快照不上传公开仓库。

管理命令：`python manage.py import_local_workbooks --directory "授权工作簿目录"` 只预览；追加 `--apply` 才分批入库。`--source all`（默认）覆盖七份文件，或选择单个来源。文件 SHA-256 与解析器版本共同定义不可变版本；同版本重复运行不新增记录。暂存实体/关系不可见，行数、关系数、隔离数与导入前后文件校验全部通过后原子发布。中断可按已提交行继续；旧版本原始记录和旧分析快照不删除。

图表读取仅折叠新工作簿中重复的中药—成分/疾病—中药结构，不删底层证据。所有靶点行仍受明确展示上限约束，导出不代表全库原始文件。大疾病优先读取所选中药三元证据，避免被其他中药的行数挤出。

本地 SQLite 预览启用 WAL 与 30 秒锁等待；默认持久性不降低。生产 PostgreSQL 配置不变，本次未在 PostgreSQL 上执行全量验收。

## 4. 本阶段迁移与验收

迁移 0023 先增加可空 UUID，再为已有行逐条生成不同 UUID，最后设为非空唯一，避免为全部旧记录写入同一个默认值。只有原 organism 明确为 Homo sapiens 的记录补 taxon 9606，其他记 unknown。

`python manage.py build_master_tables` 为只读数量检查；加 `--apply` 只建立既有 stable_id/外部观察的主表映射，不改已有整数 PK、不合并实体、不导入工作簿、不安排同步。可重复执行。

后台数据源页展示主表数量。管理员只读状态接口：`GET /api/v1/admin/master-table/`。来源映射、权威绑定、原始行可在 Django 管理后台只读核查。普通研究者不能访问管理统计和映射登记。

验收包括强标识跨库复用、同名不合并、物种隔离、基因/蛋白区分、冲突不覆盖、原始行不可变、唯一约束、旧主键与 UUID 保持、历史歧义保留、管理员权限及旧检索/R 图表回归。
