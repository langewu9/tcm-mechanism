# 网页交付演示与模块问题清单（2026-10-11）

## 交付结论与边界

当前可以交付**本地演示网页与共享源码**，不能据此宣称正式生产系统或真实科学分析全部验收完成。

入口：`/demo`，无需登录即可展示 11 个模块场景和全部 14 种现有 R 图表。真实工作区保持原有登录、所有权与管理员权限检查。演示角色选择不改变权限。

每个模块有独立合成 key、三步展示与真实功能前提；真实页面上方有本模块演示入口；每张 R 分析卡片下方有本图演示入口。真实数据不足时仍保留禁用提示，不能用合成图冒充真实分析结果。

所有演示实体、关系和医案均为虚构。演示不入业务数据库、不提交分析任务、不调用模型、不访问外部生物数据库、不启用定时同步。科研助手为标注清楚的模板回答。R 图是固定 key 的预渲染输出；页面阈值筛选不会重算这些图。R HTML 是图像与数据表的自包含包装，不是交互式 R 网络应用。

## 交付准备与演示顺序

在仓库根设置本地 R 服务地址/令牌，启动私有 R 服务，再执行：

```sh
python r_viz/test_demo_fixtures.py
python r_viz/prepare_demo_gallery.py
cd web
pnpm test:demo
pnpm build:delivery
pnpm dev --host 127.0.0.1 --port 5173
```

生成资源不进 Git；协作者重新生成，或使用交付静态演示包。令牌、模型、数据库与上传文件不放入包。共享仓库提供前后端/R 源码；静态网页包只供展示，不包含正式后台系统。

本机交付包：`D:/MMDD/deliverables/tcm-web-demo-20261011.zip`（约 8 MB）。解压后的 `site/` 是静态站点根目录，需由支持 SPA 路由回退到 `index.html` 的 HTTP 服务托管，再打开 `/demo`；不能直接双击 HTML。正式工作区仍需要 Django 后台和原有登录配置，静态包不提供这些服务。包内另附 11 模块合成 key 和本说明，图表资源已通过与构建目录同样的完整性检查。

建议演示：总览 → 药理检索 → 数据资产 → 蛋白组学阈值筛选 → 网络交集及 PPI → 医案人工审核 → 证候方药 → 助手模板 → 动态版本复核 → 接口状态边界 → 账号权限说明。最后从 R 图库选择任一图并下载 key 与 SVG/PDF。

## 正式上线最优先验收项

1. **P0：正式数据。** 确认来源使用许可，导入真实实体/关系，保留 namespace、source ID、版本、稳定主键与证据；歧义不可仅凭同名自动合并；验证更新回滚和备份恢复。
2. **P0：生产环境。** Linux Docker 构建、PostgreSQL/Redis/Celery/R 健康、域名/TLS、独立密钥、私有对象存储、SMTP、账号隔离、恢复演练与负载测试。不要把原生 Windows 预览等同正式部署。
3. **P1：真实分析。** 在明确同意和有权使用的数据上验收 PPI、富集、医案候选和引用。模型仍按用户要求不动；PCA/热图/GSEA、交互式 R 网络和旧 AI Scientist 缺失依赖列入下一轮，而非标记完成。
4. **P1：产品验收。** 小屏和键盘操作、异常/超时/权限场景、全部真实下载、长期任务恢复、数据保留策略与管理员审批实际走查。
