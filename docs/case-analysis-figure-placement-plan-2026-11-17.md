# 智能分析中的医案可视化工作区初版

日期：2026-11-17。状态：本地页面版已接入，等待用户查看；没有新增临床算法或导入数据。

## 设计目的

在 `/analysis` 智能分析中增加“医案可视化”页签，与既有“证候与网络药理分析”并列。它围绕本项目的参考医案、个人医案和单案研究流程组织，不改变现有整体风格。古今平台截图只借鉴分析方法、参数、图像、数据表与下载的摆放顺序。

工作区按“数据范围 → 分析方法 → 参数 → 图像 → 同一结果的明细与下载”排列。统计、用药特征、关联、聚类、医案关系是本项目医案分析的入口；其中只有已具备真实数据口径的图才允许生成。

## 本版实现

- `/analysis` 默认打开“医案可视化”，另一个页签保留原有证候与网络药理分析；带 `textTask` 的旧任务链接会自动打开对应分析页签，切换页签时保留任务编号。`/cases` 继续只提供参考医案检索与个人医案录入/审核，带 `caseTask` 的链接仍进入“我的医案”。
- 可切换“我的医案”和“参考医案库”。个人范围只读取当前登录者可见的未归档医案总数；因为当前 API 只提供分页记录，未把一页医案伪装成全量分布，也不从原文拆词。
- 当前唯一可以生成的图为参考库已登记的疾病类别计数。它只在参考库接口可用时开放，展示数据来自全库分类汇总；生成后可切换条形图/环形图、查看对应明细，并下载 SVG 与 CSV，图表标注版本、范围及分母。
- 每种分析配置上方放置同组件内可展开的“算法与用途”，按“算法思想/计算依据 → 基本步骤 → 结果含义”的教材式段落说明，并单独标出本项目当前状态。已实现的参考库类别计数口径为：活动语料版本中按登记 `category` 字段做数据库分组计数；图中占比按当前传入绘图类别之和计算，筛选前 N 类后分母也随显示类别变化。个人医案列表总数不是字段统计结果。
- 方法说明明确区分统计关联规则与现存的单案候选审核及版本化证据链：前者介绍支持度、置信度和提升度的标准含义，但当前没有执行接口；后者由模型候选、原文引文核验、研究者逐条确认和来源关系分层扩展组成，不能据此声称本工作区已经生成通用知识图谱。
- 用药属性、关联、聚类和医案关系页已整理参数与结果位置，但在真实输入字段/算法就绪前保持不可生成状态。关系图谱等待用户完成医案数据处理后再导入核对。
- 界面使用项目现有的纸色卡片、朱红和暖棕配色、字体和边框。蛋白组学页面没有改动。

## 按业务确定的图像与输入

| 分析入口 | 计划输出 | 必需输入/口径 | 当前状态 |
| --- | --- | --- | --- |
| 医案统计 | 疾病类别、证型、症状、四诊、治法、方剂、药物的分布图及明细 | 完整选定范围；字段结构与记录/诊次单位；比例分母 | 仅参考库登记类别计数有汇总接口；参考库当前不可用。其余字段待完整聚合数据接口 |
| 用药特征 | 药物频次、四气/五味/归经/功效分布及按需雷达图 | 原始处方记录、药物规范实体、来源明确的属性对应 | 等待处方数据和规范属性数据 |
| 关联分析 | 规则表与关联网络 | 明确的共同出现单位、前后项字段、阈值、来源记录 | 等待结构化字段；自由文本不按逗号等标点切分 |
| 聚类分析 | 树状图、聚类分布和成员表 | 明确编码后的病例/方药特征矩阵、距离和聚类方法 | 等待矩阵和方法确认 |
| 医案关系 | 可交互的症状—证候—治法—方剂—药物关系及出处 | 实体 ID、诊次 ID、经核对的关系、证据和来源 | 等待用户处理并导入医案数据 |

## 当前数据依据和限制

- `/api/v1/research/case-corpus/summary/` 提供参考库版本和类别计数；当前本机环境返回 `available: false`，因此页面显示未接通，不会出现示例图。
- `/api/v1/research/cases/` 返回个人医案分页和总数，不返回全量字段聚合。当前账号观察到的唯一记录标注为“虚构医案（非临床）”，不能作为临床图像数据。
- 新图表是前端按接口真实计数绘制的 SVG，并非 R 分析任务。还没有为医案接入 R 任务、HTML 报告或知识图谱文件下载。
- `RChartViewer`、`RAnalysisGallery` 和 `visualization.py` 是既有绘图任务/文件能力的潜在复用入口；需在医案结构化输入与任务契约明确后适配，不能仅凭页面容器声称 R 已运行。

## 数据处理约束

1. 图、表和下载必须来自同一范围和同一份结果，并标明来源、版本、记录数及占比分母。
2. 个人医案聚合仅限当前用户有权查看的记录；归档记录不纳入默认范围。
3. 不依据标点拆分药物或症状，不将相似名称自动合并，也不从自然语言猜边。
4. 共同出现、统计关联和知识图谱分别说明；关联不能解释为因果。
5. 数据或算法缺失时显示明确原因，图像生成入口不可执行。

## 后续接入顺序

1. 用户完成医案数据处理并提供需导入的数据。
2. 对齐医案/诊次单位、结构字段、药物与证候实体、来源和关系证据。
3. 为完整授权范围实现统计汇总，不依赖分页前端拼数。
4. 按数据实际情况启用相应图像，先核对少量来源记录和图表分母，再扩展范围。
5. 最后适配已有 R 绘图任务和 HTML/图片/数据下载；知识图谱只在实体、诊次与关系都能追溯后启用。
