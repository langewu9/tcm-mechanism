## 关键修复

1. 统一通过版本化来源映射连接原主表。来源编号不同的同名实体独立保留；物种未知且缺少可核验标准编号的记录不自动视作人类。
2. 标准交集先投影匹配实体的全部有效关系中的不同靶点主键，防止早期来源的重复行占满上限后遮住新来源。原始证据导出、候选表及网络图仍保留展示上限，页面分别说明范围。
3. 新 TCMSP 数据和标准映射在同一发布事务中切换。旧 TCMSP 关系保留为停用历史；失败可按检查点重跑，重复导入不会重复记账。
4. 预测关系与源表 validated 标记分别记录。SVM/RF 分值保存在来源元数据，不转换为 P 值、FDR 或临床证据。
5. 化合物属性逐字段提供原始记录号与版本。真实数值0保留，缺失值和冲突值为 null；不求平均，不补成0。目录和成分检索支持精确 TCMSP MOL 编号。
6. Windows Docker 挂载使用原 SQLite；完成安全检查点后切换为 DELETE 日志模式。SQLITE_WAL_ENABLED=false 会明确设置 DELETE，避免文件遗留 WAL 模式导致 Docker 连接失败。

## 待复核范围与更新方式

TCMSP 尚有228,683条来源行隔离，原因包括缺失/不在当前 reviewed-human 参考范围内的编号、名称不一致、歧义名称、靶点未核验或异常额外列。它们是待核验来源记录，不应统一解释为错误数据；非人类或参考范围之外的蛋白不在本轮人类核验范围内。

BATMAN名称表中6,633行暂不能唯一对应本项目既有中药，已保存待核查，不创建虚构实体或关联。名称别名只影响检索，不作为身份合并证据。

定时自动同步保持关闭，符合先统一主表、再安排更新的顺序。本轮完成的是本地快照导入与可重复发布链路；未声称全部数据库已具备官方实时API。外部ChEMBL/API本轮仅复测同意与参数边界，没有新增在线数据抓取。

后续新工作簿使用新暂存文件：只读核对文件与参考版本 → prepare → 核验隔离分类及计数 → apply → 原子切换 → 回归查询。Windows 原 SQLite 正式写入前应暂停 api/worker/r-worker，完成单一环境写入与检查点后再恢复服务，避免宿主机和Docker并发写同一个文件。两个管理命令见源码：import_tcmsp_bundle、import_batman_names。原始工作簿、SQLite、暂存库与模型不上传公共仓库。
