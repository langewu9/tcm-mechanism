## 复现的问题与修补

| 问题及复现依据 | 处理 |
| --- | --- |
| 合成来源中两味中药共用一个成分；原工作台只沿成分 ID 遍历，另一味中药原行的靶点和通路也进入当前结果 | 复用检索/网络药理已有 `supported_target_queryset`，旧三元来源必须匹配所选中药的来源版本和整数原行号；普通图关系仍保留其原有语义 |

| 证候任务中的关系未保留原行号及完整端点身份 | 冻结关系 ID、端点 ID/stable ID、来源 release/校验值和原行等当前已知字段；历史不回填 |
| CSV 只有关联清单，缺少输入、无匹配状态及截断提示 | 附带任务号、名称、问题、状态、摘要、额度和警告；保留公式转义，新关系携带已冻结身份字段 |
| PostgreSQL JSONB 返回字段的顺序与原链路顺序不同 | 页面及 CSV/PDF 均固定“证候→方剂→中药→成分→靶点→基因→通路”顺序 |
| 实际渲染发现空结果 PDF 多一张仅有页脚的空白页 | 删除尾部空白、合并缺少关联的层级说明、标题与正文保持相连；两个空结果报告最终均为一页 |

## 当前真实资料的限制

本地工作 PostgreSQL 中活动实体计数：证候 **0**、方剂 **0**、中药 **8,203**。四组关键词样例均返回 `catalog_missing`、零来源关系；无关键词样例返回 `no_rule_match`。已有中药—成分—靶点资料不能自行补成证候—方剂关联。

因此：完整正向链路的来源约束、停用过滤、身份、权限和医案归属由临时测试库的合成夹具验证；临时导出样例含 6 条合成关系、1 个合成靶点，不写入工作库。**真实证候/方剂资料、医案研究样例及临床有效性尚未验收。** 后续需要有明确出处的证候—方剂、方剂—中药关系，不从药名、疾病名或模型猜测组成。
