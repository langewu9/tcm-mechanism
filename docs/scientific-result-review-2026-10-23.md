## 有证据的问题与风险

### 1. 数字逗号会被静默删除——应优先修补的输入问题

位置：`python_app/apps/proteomics/services.py:332-345`、`raw_matrix.py:20-34`。

纯函数实际探针：差异统计输入 `0,01` 被解析为 `1.0`；已声明 log2 尺度的矩阵值 `1,2` 被解析为 `12.0`。解析器没有核对小数/千分位格式，而是先删除全部逗号。若研究者使用小数逗号或不规范千分组，数值可能被静默改变。

**当前保存的六份原文件未触发该格式，不能说已保存结果因此错误。** 建议明确允许的数值语法和格式，歧义值拒绝并定位行列；不能自动猜成小数，也不涉及拆分或合并成分/蛋白标签中的逗号。

### 2. “共同靶点 / 交叉验证 / 未检出”超出了当前名称重叠的依据

位置：`python_app/apps/proteomics/services.py:599-620`、`web/src/pages/ProteomicsPage.tsx:712-717`。

服务对非空 `normalized_symbol` 作集合交集，没有要求身份已经核实。READ ONLY 探针复用 #36 原文件，提供 `MAPK1`、`SYNTHETICX`、`NOT_ACTUALLY_MEASURED` 三个参考项：数据库确认映射为 0，仍得到 `overlap=[MAPK1,SYNTHETICX]`，二者均为 `unverified`。第三项进入 `referenceOnly`。

全局未核实警告仍存在，但交集本身不包含物种/规范编号确认。“不在本次选中符号集合”也不能证明“实验未测到”。建议区分未核实符号重叠与有来源、物种及身份依据的交集，保留每个成员的状态，并调整“未检出”措辞。

**现存所有蛋白组学任务的 `referenceTargets` 都为空，没有已保存的错误共同靶点实例。** 上述探针没有保存任务。

### 3. 退化常量行的 P=1 是未明示的统计约定，会改变 BH 检验集合

位置：`python_app/apps/proteomics/raw_matrix.py:348-374`。

两组样本完全相同、标准误为 0 时，程序直接赋 P=1，并计入完成检验及 BH。仅在内存向现有矩阵追加一行两组均为 `[10,10,10]`：项目完成检验从 3 变 4；R Welch 对该行报不可估计，配对 R 返回 NaN。R 参照保留 3 个有限检验。

例如非配对原 `row_index=0`（零基编号）行 FDR 从 R 参照的 `0.0111567977084292` 变为项目的 `0.014875730277905582`。此例使 FDR 增大，**不是制造显著性**。问题在于输出未明示这项保守赋值约定及检验家族变化，不能不加说明地将该行称为成功执行了 t 检验。

应先明确统计策略：将其标为不可估计，或显式声明和记录保守 P=1 及 BH 集合政策；不能仅为贴合某个参照而悄悄更改历史结果。当前保存 #33/#34 不包含新增常量行，其原结果本轮与 R 一致。

公共方法依据：R 官方说明常量输入可能使 t 检验报错，BH 调整还依赖比较次数。它也允许显式扩大比较次数并将未观察 P 按 1 处理，所以本报告将此列为**需声明和确认的统计政策**，不武断认定保守赋值必然数学错误。[R t.test](https://stat.ethz.ch/R-manual/R-devel/library/stats/html/t.test.html)、[R p.adjust](https://stat.ethz.ch/R-manual/R-devel/library/stats/html/p.adjust.html)。本轮只读取公共方法文档，没有发送项目数据；官方文档不替代本机 R 实际复算依据，也不能验证本项目生物学结论。

原始探针 JSON 的配对 `rRowsTested=4` 是 R 返回行数，含一条 P/FDR=NA，有限检验实际为 3；已用独立 clarification 文件解释，未覆盖原证据。

### 4. 外来差异表的筛选政策不能统称为统一 FDR 控制

位置：`python_app/apps/proteomics/services.py:372-410`。

既有规则有 FDR 时优先用 FDR，缺失时回退原始 P。实际合成 #12 的 `row_index=3`、#36 的 `row_index=11`（均为零基编号）输入 P=0.9/FDR=0.01，均按 FDR 通过；另两行缺 FDR，按 P=0.01 通过。

如果这些值被声明为同一检验集合的标准 BH 调整结果，前一组值不相容；但当前外来列没有这种方法声明，不能将全部 q-value/FDR 定义一概当成 BH。混用原始 P 和调整值筛选也不能直接声称最终集合统一满足 FDR≤0.05。建议保存上游统计方法、校正方法和检验集合，明确标为按输入列筛选，并让图表说明与实际策略一致。

火山图颜色确实取已保存 selected；R caption 已说明底色/虚线仅标坐标阈值，不能说图色完全错误。但 subtitle 只写 log2FC/P 阈值，容易漏掉实际 FDR 优先政策。**这些输入是刻意合成边界；平台自行计算矩阵 BH 的两份保存结果本轮已经独立验证。**
