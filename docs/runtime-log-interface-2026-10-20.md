# 近期异常日志查询接口

本次只增加维护用的只读 JSON 接口及 Django 后台首页链接，不新增研究者页面或完整日志中心，不修改研究算法、结果内容或数据库表。

## 使用方式

登录 Django 管理后台后，在“平台维护工具 → 近期异常日志（只读接口）”查看：

```http
GET /api/v1/admin/runtime-logs/
GET /api/v1/admin/runtime-logs/?task_id=123&limit=20
GET /api/v1/admin/runtime-logs/?request_id=00000000-0000-4000-8000-000000000001
GET /api/v1/admin/runtime-logs/?level=error&since=2026-10-20T00%3A00%3A00Z
```

- `task_id`：正整数，查询分析任务执行/入队失败；不等同于数据源同步运行编号。
- `request_id`：合法 UUID，对应响应的 `X-Request-ID`，用于查询 HTTP 异常。异步 worker 记录使用任务编号，不伪造与原请求的关联。
- `level`：`warning` 或 `error`。
- `since`：ISO 8601 时间，建议明确写 `Z` 或时区偏移；带 `+` 的偏移需要 URL 编码。
- `limit`：默认 50，最大 100。参数可组合；重复参数、未知参数或无效值返回统一 400。不支持文件名、目录或任意文件读取参数。

返回 `results`（时间倒序）、`limit`、`hasMore`、`scanTruncated` 和 `skippedRecords`。每条包含事件编号、时间、固定事件分类/说明、任务/请求编号、路由名称、HTTP 方法/状态、异常类型及最多 12 个模块/函数/行号。

`hasMore` 仅表示本次扫描窗口中有更多匹配项，可增大返回数量或缩小筛选范围，不提供完整历史分页。`scanTruncated=true` 表示仍有文件内容在查询窗口之外；空列表不证明任务从未失败。`skippedRecords` 表示跳过的损坏或不受支持的记录，损坏内容不会直接返回。

## 权限与敏感信息

账号必须同时为已登录、有效、staff、superuser。普通研究者、拥有所有模型权限的普通 staff、停用账号及非 staff 超级管理员均不能读取。仅接受 GET/HEAD/OPTIONS，不能通过接口修改或删除文件。

沿用 session、限流和 `private, no-store`；成功读取写入现有敏感访问审计，仅保存查看者、操作、时间和当前查询请求编号，不复制筛选条件或异常内容。审计保存失败时扣留日志响应并返回 503。

写入前限制字段，读取时再次重建允许字段。不保存或返回请求正文、查询字符串、URL 路径、Cookie、密码、令牌、模型提示词、医案正文、研究结果、原始异常消息、源码文本、局部变量或完整文件路径。保留的是脱敏定位信息，不是原始技术堆栈；更详细上下文仍由维护人员查看服务端原始日志。

## 保存、覆盖范围和部署

- 默认目录 `python_app/var/runtime-logs`，可用 `RUNTIME_LOG_DIR` 指定私有绝对路径，不得放入公开静态目录或配置 Nginx 文件直出。
- 使用 Linux `flock` 协调 API/worker 多进程写入和轮转；目录初建权限 0700，记录和锁文件初建权限 0600。拒绝符号链接和特殊文件，锁等待上限 100ms，需要支持本机 POSIX 锁的文件系统。
- 每文件最多 1 MiB，保留当前文件和 3 个备份，总计约 4 MiB，不承诺固定保留天数。每条最大 8 KiB，单次查询最多扫描最近 1 MiB。
- 收集本版本加载后的 API 5xx/未处理异常，以及蛋白组学、医案分析、科研助手、外部分析、R 绘图的入队/执行失败。正常请求、成功任务、同步运行、启动/退出、Celery 硬终止及独立 R 服务原始日志不在覆盖范围内。不会导入既有历史 stdout/日志文件。
- 文件写入失败只记录服务端安全告警，不阻断原有任务状态保存或替换原有 API 错误；查询文件不可用返回安全 503。可轮转诊断信息不代替必须保存的访问审计。
- 本地 API 和 worker 需重启加载记录点。容器配置已为两者增加共享私有日志卷，生产镜像创建归属应用账号的目录，Nginx 不挂载日志卷。部署时重建镜像并重新创建 API/worker，无需数据库迁移。

验证使用临时日志目录、临时测试数据库、合成异常和模拟服务，不触发真实模型或外部生物数据请求。权限、脱敏、限量、轮转、并发完整性、审计失效拒绝、文件/锁异常降级及业务任务失败状态均有回归覆盖。

验证结果：PostgreSQL 全部 470 项通过（50.730 秒）；SQLite 470 项中 469 项通过、1 项跳过（46.949 秒），跳过项仍为不支持行锁的原有并发额度测试。严格 OpenAPI 校验、迁移一致性及两份 Compose 私有卷配置检查通过。独立 HTTP 会话验证匿名拒绝、后台链接、管理员 JSON 查询、禁止写方法、拒绝路径参数和不缓存，临时会话已注销。本地 PostgreSQL API/worker 已重启加载；旧 SQLite 预览未停止，研究者前端未改动，未推送远程。
